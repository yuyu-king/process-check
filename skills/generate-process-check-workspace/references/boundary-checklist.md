# 边界 / 条件用例清单

只为**代码或规格里确实存在**的校验生成用例。没有证据就不要猜状态码（尤其不要默认 400）。

优先覆盖 POST / PUT / PATCH。GET 仅在有查询参数校验、鉴权或 404 分支时建用例集。

## 每条用例怎么写

- `overrides` 只写相对 API 库请求需要变化的字段（深合并；数组整体替换）。
- `assertions[].source` 相对于这一次响应：`status`、`ok`、`body.*`。
- 正常路径与失败路径都要有证据中的真实 status / 关键字段。
- 需要登录的接口设置 `caseSet.actorId`；公开接口省略。
- 「未登录」用例：不要复用会自动登录的 Actor。单独建一个无 `login.url` 的 Actor，或该用例集不设 `actorId`（仅当服务端对缺凭证有可观察失败时）。

## 有证据才收录

**正常路径**

- 合法必填字段、合法枚举、文档中的成功 status（常见 200/201）。
- 成功体里后续流程会用到的字段用 `exists`（如 `body.id`）。

**请求体 / 查询**

- 缺必填（字段删除，不要只赋 `null`，除非实现把 null 当缺省）。
- 空字符串、只含空白（若实现 trim / 拒绝空白）。
- 类型错误（字符串字段给 number 或反过来），且框架/手工校验会拒绝。
- 长度：min-1、max、max+1（来自 `@Size` / `maxlength` / `len()` 等）。
- 数值：min-1、min、max、max+1。
- 非法枚举 / 非法常量。
- 格式：email、URL、日期、UUID（仅当有格式校验）。
- 唯一冲突 / 重复创建（实现返回 409 或业务码时）。

**鉴权与资源**

- 未登录 / 缺 Token → 实现返回的 401（或项目自定义码）。
- 已登录但角色不足 → 403。
- 他人资源 / 错误 ID → 404 或 403（以实现为准）。
- 状态不允许的操作（已审批再批、已删除再改）→ 实现中的冲突码。

**不要编造**

- 实现没有校验的「类型错误 400」。
- 无法从响应、outbox、mock 观察到的副作用。
- 与当前接口无关的字段组合。
